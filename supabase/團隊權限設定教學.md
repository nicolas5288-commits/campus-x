# 後台夥伴權限 — 設定教學（一次設定，之後在後台點一點就能加人）

做完這份設定後：你可以在後台自己新增合作夥伴當審核員，他們能做**全部的內容審核**，但**動不了任何人的權限**。

程式都寫好了，你只要做 2 步（約 5 分鐘）。

---

## 誰能做什麼

| | 你（主理人 owner） | 合作夥伴（審核夥伴 mod） |
|---|---|---|
| 廠商投稿：通過上架 / 退回 / 編輯 / 永久刪除 | ✅ | ✅ |
| 學生心得、大使名片、活動、計畫回報：全部審核動作 | ✅ | ✅ |
| 已上架內容下架、許願池管理 | ✅ | ✅ |
| 數據總覽 | ✅ | ✅ |
| **新增 / 移除審核夥伴** | ✅ | ❌ 看不到「團隊」分頁 |

「夥伴不能改權限」是**資料庫層擋住的**——就算對方懂技術、繞過網頁直接打 API，一樣會被拒絕，不是只把按鈕藏起來而已。

---

## 第 1 步：跑 SQL（2 分鐘）

到 [Supabase 後台](https://supabase.com/dashboard) → 你的專案 → **SQL Editor** → 貼上執行：

```
supabase/schema_v18_staff_roles.sql
```

這段做三件事：
1. 建一張 `staff` 團隊名單表，並把你的 email 放進去設成 owner
2. 把全站的「你是不是管理員」判斷，從「寫死一個 email」改成「查這張名單」
3. 鎖死名單本身：只有 owner 能增刪，夥伴只能看

**跑完怎麼驗**，在 SQL Editor 貼這行：

```sql
select * from staff;
```

看到 `chiwen5288@gmail.com` / `owner` 那列就對了。

> ⚠️ **不要用 `select is_admin();` 來驗**。SQL Editor 是用資料庫管理員身分直連，沒有「登入者」的身分憑證，所以 `is_admin()` / `is_owner()` / `get_my_role()` 在這裡**永遠回 false / false / null**。那是正常的，不代表沒裝好——這幾個函式是設計給網站前端呼叫的。
>
> 真正的驗證：用你的帳號登入 [審核後台](https://uniembassy.tw/admin.html)，分頁列最右邊出現「👥 團隊」就成了。

如果跑的當下報 `stack depth limit exceeded` → SQL 沒跑完整，整份重貼一次。

> 💡 貼上時如果報 `syntax error`，多半是整段太長被截斷。把檔案分成「建表 / is_admin / is_owner＋get_my_role / policy」四段分開貼。

## 第 2 步：重新部署通知信函式（3 分鐘，不用裝任何工具）

夥伴按「通過上架」時，廠商通知信也要寄得出去，所以那支函式的權限判斷要一起更新
（原本只認單一 email，改成查 staff 名單）。

跟你當初第一次部署它的方式一樣，走 Supabase 網頁後台：

1. Supabase 後台 → 左側 **Edge Functions** → 點 **notify-approved**
2. 找 **Edit function**（或 Deploy new version → Via Editor）
3. 把 `supabase/functions/notify-approved/index.ts` 的**整份內容**貼進去覆蓋舊的
4. 按 **Deploy**

> 💡 本機沒裝 Supabase CLI，所以 `supabase functions deploy ...` 那種指令貼終端機會說「找不到指令」。走網頁後台就好，不用為了這件事去裝 CLI。

沒做這步的話：夥伴審核照常，但他按上架時廠商**不會收到通知信**（你自己按則正常）。不會壞掉，只是漏信。

**驗證**（終端機，回 403「只有管理員能觸發通知信」＝部署成功）：

```bash
curl -s -X POST "https://xjoggvwngsvowjnwwrnc.supabase.co/functions/v1/notify-approved" -H "apikey: sb_publishable_JQ0K7GNF7KbhzqNHQvHi-A_SWIaUwo4" -H "Content-Type: application/json" -d '{}'
```

## 之後要加人：3 步，不用再碰程式

1. 請夥伴先用 **Google 登入過網站一次**（確認他用哪個 Gmail）
2. 你到 [審核後台](https://uniembassy.tw/admin.html) → **👥 團隊** 分頁 → 輸入他的 Email → **＋ 加入團隊**
3. 請他重新整理頁面 → 頭貼選單就會出現「🛠️ 審核後台」

**移除也是即時生效**：在同一頁按「🗑️ 移除」，他下一個動作就會被擋下來。

---

## 常見狀況

**夥伴說看不到後台入口**
→ 確認你加的 Email，跟他實際登入用的 Google 帳號是同一個（很多人有多個 Gmail）。請他登出再重新用 Google 登入。

**我可以把自己移除嗎？**
→ 不行，這是刻意的。主理人那列沒有移除鈕，資料庫也擋著——避免手滑把自己踢掉之後沒人能進後台。

**夥伴會看到廠商的聯絡 Email 嗎？**
→ 會。審核要聯繫廠商本來就需要。這是加人前要考慮的信任範圍。

**夥伴刪掉的東西救得回來嗎？**
→ 「永久刪除」是真的刪掉、救不回來（跟你自己用是一樣的）。加人前提醒對方：退回用「✕ 退回」，垃圾資料才用「🗑️ 永久刪除」。

**還沒跑 SQL 的話會怎樣？**
→ 網站照常運作，維持原本的單人模式（只有你進得去後台），後台會跳一則「團隊權限的資料庫設定還沒跑」提示。不會壞掉。
