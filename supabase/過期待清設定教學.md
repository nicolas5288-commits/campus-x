# ⏰ 過期待清：設定教學（約 5 分鐘，只要做一次）

## 這套在做什麼

- **每天早上 9:17（台灣時間）**，GitHub Action 自動檢查：截止日已過、或被標成「已截止」，但還在上架的計畫
- 有的話就寄一封對照表到你的信箱（附 CSV），信裡有「到後台確認」按鈕
- **系統不會自己動任何資料。** 你要到後台「⏰ 過期待清」分頁勾選、按「下架」、再按一次確認，才會下架
- 下架＝狀態改成「已截止」（closed）：心得、收藏、回報全部保留，可以在「已下架」一鍵重新上架；廠商查稿頁會顯示「📁 已截止」，不是「退回」
- 專屬頁 `/p/…/` 會在下次自動重生（6 小時內）時拿掉，重新上架後也會自動長回來

## 你要做的事：部署雲端函式（不用裝任何工具）

1. Supabase 後台 → 左側 **Edge Functions** → **Deploy a new function** → 選 **Via Editor**
2. 函式名稱填：`expired-programs`（一字不差，排程是用這個名字叫它）
3. 把 `supabase/functions/expired-programs/index.ts` 整份內容貼進編輯器 → 按 **Deploy**
4. ⚠️ **部署完點進這支函式 → 設定（Details / Settings）→ 把「Verify JWT」（或叫 Enforce JWT verification）關掉 → 存檔**
   - 為什麼：每天叫它的是 GitHub，GitHub 給的身分證不是 Supabase 格式，不關的話會被擋在門口
   - 安全嗎：安全。函式自己會驗身分——只認「campus-x 這個 repo 的 main 分支上的這支排程」，或「團隊名單裡的登入者」，其他人一律 403
   - **不用設任何新的 Secret**：寄信沿用 `notify-approved` 已經設好的 `RESEND_API_KEY`、`FROM_EMAIL`、`REPLY_TO`

## 驗證有沒有成功（三選一）

- **最簡單**：登入後台 → 「⏰ 過期待清」分頁 → 按「📧 寄測試信給我」→ 收到信就成功了
  - 分頁上方如果出現黃色提示「收藏數要等 expired-programs 函式部署好才看得到」＝函式還沒部署好
- **測排程本身**：GitHub repo → **Actions** → 「過期計畫每日清單」→ **Run workflow**，綠勾＝成功、信會寄到主理人信箱
  - 紅叉的話點進去看錯誤：`404`＝函式沒部署或名字打錯；`401`＝第 4 步 Verify JWT 沒關；`403`＝repo／分支／檔名對不上
- **終端機**：`curl -s -o /dev/null -w '%{http_code}\n' -X POST https://xjoggvwngsvowjnwwrnc.supabase.co/functions/v1/expired-programs` 回 `403`＝部署好、Verify JWT 也關了（回 401＝還沒關，回 404＝還沒部署）

## 之後要改什麼

- **寄信時間**：改 `.github/workflows/expired-programs-digest.yml` 的 cron（是 UTC 時間，台灣要減 8 小時）
- **過期規則**：`db.js` 的 `expiryOf` 和 `supabase/functions/expired-programs/index.ts` 的 `expiryOf` 是同一套，**改一邊要改另一邊**，改完函式要重新貼上部署
- **收件人**：寄給 staff 團隊名單裡所有 owner（目前只有你）；後台按「寄測試信給我」則只寄給按的人
- 清單是空的那天不會寄信
